Kinotic runs on your own machine today. Kinotic OS Cloud, where Kinotic runs for you, is coming soon.

::tabs{sync="kinotic-install"}

:::tabs-item{label="Local" icon="i-lucide-laptop"}

The local install runs the whole of Kinotic OS in Docker on your machine: its servers, the portal, the
Git server that holds your projects' repositories, and the storage your apps' data and UIs live in.
Nothing leaves your machine except the downloads.

#### Prerequisites

- **Docker** with Compose, running, with at least 12 GB of memory available to it
- **Node.js** 18 or later, which the Kinotic CLI runs on
- **macOS on Apple silicon, or Linux with KVM** (`/dev/kvm`), where your apps' deployments run as micro VMs
- **Claude Code**, which builds your app with the Kinotic plugin
- An internet connection for the first start, which downloads Kinotic, and for each new project, whose starting code comes from GitHub

::::steps{level="4"}

#### Install and launch Kinotic

```bash
curl -fsSL https://kinotic.ai/install | sh
```

This installs [Bun](https://bun.sh) if you don't have it, installs the Kinotic CLI, and runs
`kinotic local up`, which starts Kinotic and the node your projects deploy to. The first start downloads
everything and prepares the database, which takes a few minutes; the command returns once Kinotic is
ready. With the CLI already installed, `kinotic local up` alone starts it.

#### Create your organization

Open [http://localhost:9090/signup](http://localhost:9090/signup), enter your name and email, then name
your organization and set a password. A local install sends no email, so the page goes straight on, and
you are signed in to your new organization.

#### Follow the Quickstart in the portal

Open **Quickstart** in the portal's sidebar. It walks you through installing the Kinotic plugin in Claude
Code, connecting Claude to your local Kinotic, and asking for your app. Claude creates the application
and its project, writes the entities, services and UIs, and pushes to the project's repository; every
push deploys.

The plugin brings its own MCP server, `plugin:kinotic:kinotic-os`, which connects to Kinotic Cloud. Your
local Kinotic is a second server, `kinotic-local`, which the Quickstart has you add. In Claude Code's
`/mcp` list, authenticate `kinotic-local` and leave the plugin's server as it is:

```text
User MCPs
❯ ⚠ kinotic-local                needs authentication    ← authenticate this one

Built-in MCPs
  ⚠ plugin:kinotic:kinotic-os    needs authentication    ← Kinotic Cloud, leave it
```

::::

`kinotic local down` stops Kinotic and the apps it deployed, and keeps your data for the next `kinotic local up`;
`kinotic local down --delete-data` deletes it. `kinotic local status` and `kinotic local logs` show what
it is doing, and the [CLI reference](/apps/cli-reference#kinotic-local) covers each command.
[Developing Kinotic](/platform/contributing) covers how to work on Kinotic itself.
