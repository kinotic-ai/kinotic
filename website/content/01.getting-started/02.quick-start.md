Run Kinotic on your own machine, or try Kinotic Cloud, where Kinotic runs for you, free while it is in beta.

::tabs{sync="kinotic-install"}

:::tabs-item{label="Local" icon="i-lucide-laptop"}

The local install runs the whole of Kinotic OS in Docker on your machine: its servers, the portal, the
Git server that holds your projects' repositories, and the storage your apps' data and UIs live in.
Nothing leaves your machine except the downloads.

#### Prerequisites

- **Docker** with Compose, running, with at least 12 GB of memory available to it
- **Node.js** 18 or later, which the Kinotic CLI runs on
- **macOS on Apple silicon, or Linux with KVM** (`/dev/kvm`), where your apps' deployments run as micro VMs
- **Claude Code, Codex or Grok Build**, which builds your app with the Kinotic plugin
- An internet connection for the first start, which downloads Kinotic, and for each new project, whose starting code comes from GitHub

::::steps{level="4"}

#### Install and launch Kinotic

```bash
curl -fsSL https://kinotic.ai/install | sh
```

This installs [Bun](https://bun.sh) if you don't have it, installs the Kinotic CLI, adds Bun's bin
folder to your `PATH` in your shell's profile if it isn't there yet, and runs `kinotic local up`, which
starts Kinotic and the node your projects deploy to. The first start downloads everything and prepares
the database, which takes a few minutes; the command returns once Kinotic is ready. Open a new terminal
to use `kinotic` there. With the CLI already installed, `kinotic local up` alone starts it.

To update the CLI, run `kinotic local down`, then the same line again.

#### Create your organization

Open [http://localhost:9090/signup](http://localhost:9090/signup), enter your email, then your name,
your organization's name and a password. A local install sends no email, so the page goes straight on, and
you are signed in to your new organization.

#### Follow the Quickstart in the portal

Open **Quickstart** in the portal's sidebar and choose the AI you use: Claude (Claude Code), ChatGPT
(Codex) or Grok (Grok Build). The page gives you one message to copy and paste into a new session of
that coding agent. The message has the agent install the Kinotic plugin, add your local Kinotic as
the `kinotic-local` MCP server, tell you how to sign in, and ask what you want to build. The page
also lists the same setup under **Prefer to set it up yourself?**, for doing it by hand.

Sign in as the agent tells you, and approve the consent screen that opens in your browser. Then say
what you want to build: the agent creates the application and its project, writes the entities,
services and UIs, and pushes to the project's repository; every push deploys. The Quickstart checks
off the sign-in, the project and its first deployment as they happen.

For local use, the agent connects to your Kinotic through `kinotic-local`. In Claude Code's `/mcp`
list, authenticate `kinotic-local`. Don't worry about `plugin:kinotic:kinotic-os` in the same list:
the Kinotic plugin adds it for use with Kinotic Cloud, and local use doesn't need it.

```text
User MCPs
❯ ⚠ kinotic-local                needs authentication    ← for local use: authenticate it

Built-in MCPs
  ⚠ plugin:kinotic:kinotic-os    needs authentication    ← for Kinotic Cloud: not needed locally
```

If you also work on Kinotic Cloud, authenticate both: the agent works on each project through the
server that holds it, and asks which one to create a new app on.

::::

`kinotic local down` stops Kinotic and the apps it deployed, and keeps your data for the next `kinotic local up`;
`kinotic local down --delete-data` deletes it. `kinotic local status` and `kinotic local logs` show what
it is doing, and the [CLI reference](/apps/cli-reference#kinotic-local) covers each command.
[Developing Kinotic](/platform/contributing) covers how to work on Kinotic itself.
