## Entity Decorators

These decorators are imported from `@kinotic-ai/persistence`.

### `@Entity(multiTenancyType?, entityType?)`

Marks a class as a Kinotic entity. Required for any class that should be persisted and managed by the entity service system.

```typescript
import { Entity, MultiTenancyType, EntityType } from '@kinotic-ai/persistence'

@Entity()
export class Product {
    // ...
}

@Entity(MultiTenancyType.SHARED)
export class TenantProduct {
    // ...
}

@Entity(MultiTenancyType.NONE, EntityType.STREAM)
export class SensorReading {
    // ...
}
```

**Parameters:**
- `multiTenancyType` — `MultiTenancyType.NONE` (default) or `MultiTenancyType.SHARED`
- `entityType` — `EntityType.TABLE` (default) or `EntityType.STREAM`

## ID Decorators

### `@AutoGeneratedId`

Marks a field as a server-generated ID. The field type must be `string | null` since the ID is `null` before the entity is saved.

```typescript
import { Entity, AutoGeneratedId } from '@kinotic-ai/persistence'

@Entity()
export class Product {
    @AutoGeneratedId
    id: string | null = null
}
```

### `@Id`

Marks a field as a manually-assigned ID. The field type is `string` since the caller is responsible for providing the value.

```typescript
import { Entity, Id } from '@kinotic-ai/persistence'

@Entity()
export class Product {
    @Id
    sku: string = ''
}
```

## Field Decorators

### `@NotNull`

Marks a field as required. The persistence layer will reject entities where this field is missing or null.

```typescript
import { Entity, AutoGeneratedId, NotNull } from '@kinotic-ai/persistence'

@Entity()
export class Product {
    @AutoGeneratedId
    id: string | null = null

    @NotNull
    name: string = ''
}
```

### `@Text`

Enables full-text search indexing on a string field. By default, string fields are indexed as keywords (exact match only). Adding `@Text` enables tokenized search.

```typescript
import { Entity, AutoGeneratedId, Text } from '@kinotic-ai/persistence'

@Entity()
export class Article {
    @AutoGeneratedId
    id: string | null = null

    @Text
    body: string = ''
}
```

### `@DateTime`

Stores a string field as a date, so it can be sorted and range-queried by time. Entities travel as JSON, where a date is an ISO-8601 string, so a date field is a `string` (or a `string[]` for a list of dates) holding values such as `Date.prototype.toISOString()` returns. Applying it to a field of any other type is a compile error, and `kinotic generate` rejects a field typed `Date`.

```typescript
import { Entity, AutoGeneratedId, DateTime } from '@kinotic-ai/persistence'

@Entity()
export class Invoice {
    @AutoGeneratedId
    id: string | null = null

    @DateTime
    issuedAt: string = new Date().toISOString()

    @DateTime
    paidAt: string | null = null
}
```

### `@Precision(PrecisionType)`

Sets the numeric precision for a number field. Controls how the value is stored in Elasticsearch.

```typescript
import { Entity, AutoGeneratedId, Precision, PrecisionType } from '@kinotic-ai/persistence'

@Entity()
export class Measurement {
    @AutoGeneratedId
    id: string | null = null

    @Precision(PrecisionType.DOUBLE)
    value: number = 0

    @Precision(PrecisionType.LONG)
    timestamp: number = 0
}
```

**Precision types:** `PrecisionType.INT`, `PrecisionType.SHORT`, `PrecisionType.LONG`, `PrecisionType.FLOAT`, `PrecisionType.DOUBLE`

### `@NotIndexed`

Excludes a field from Elasticsearch indexing. The field is still stored and returned in queries, but cannot be searched or filtered on.

```typescript
import { Entity, AutoGeneratedId, NotIndexed } from '@kinotic-ai/persistence'

@Entity()
export class Document {
    @AutoGeneratedId
    id: string | null = null

    @NotIndexed
    rawData: string = ''
}
```

### `@Flattened`

Uses Elasticsearch flattened mapping for an object field. All values in the object are indexed as keywords, enabling filtering without the overhead of dynamic field mappings.

```typescript
import { Entity, AutoGeneratedId, Flattened } from '@kinotic-ai/persistence'

@Entity()
export class Event {
    @AutoGeneratedId
    id: string | null = null

    @Flattened
    metadata: Record<string, string> = {}
}
```

### `@Nested`

Uses Elasticsearch nested mapping for an array of objects. Preserves the relationship between fields within each object, enabling accurate queries across object boundaries.

```typescript
import { Entity, AutoGeneratedId, Nested } from '@kinotic-ai/persistence'

@Entity()
export class Order {
    @AutoGeneratedId
    id: string | null = null

    @Nested
    lineItems: LineItem[] = []
}
```

## Relationship

### `@Discriminator(propertyName)`

Marks a field as a polymorphic type discriminator. Used when a field can contain different types and the system needs to determine the concrete type during deserialization.

```typescript
import { Entity, AutoGeneratedId, Discriminator } from '@kinotic-ai/persistence'

@Entity()
export class Notification {
    @AutoGeneratedId
    id: string | null = null

    @Discriminator('type')
    payload: EmailPayload | SmsPayload | null = null
}
```

**Parameters:**
- `propertyName` — The name of the property within the object that identifies its type

## Multi-tenancy

### `@TenantId`

Marks a field as the tenant identifier. Used with `MultiTenancyType.SHARED` entities to partition data by tenant.

```typescript
import { Entity, AutoGeneratedId, TenantId, MultiTenancyType } from '@kinotic-ai/persistence'

@Entity(MultiTenancyType.SHARED)
export class Invoice {
    @AutoGeneratedId
    id: string | null = null

    @TenantId
    tenantId: string = ''
}
```

## Versioning

### `@Version`

Enables optimistic locking for the entity. The field type must be `string | null`. The persistence layer uses this field to detect concurrent modifications.

```typescript
import { Entity, AutoGeneratedId, Version } from '@kinotic-ai/persistence'

@Entity()
export class Product {
    @AutoGeneratedId
    id: string | null = null

    @Version
    version: string | null = null

    name: string = ''
}
```

---

## Time Series

### `@TimeReference`

Marks a field as the time reference for stream entities. Used with `EntityType.STREAM` to identify the timestamp field. Pair it with `@DateTime` so the field is stored as a date.

```typescript
import { Entity, AutoGeneratedId, TimeReference, DateTime, EntityType, MultiTenancyType } from '@kinotic-ai/persistence'

@Entity(MultiTenancyType.NONE, EntityType.STREAM)
export class SensorReading {
    @AutoGeneratedId
    id: string | null = null

    @TimeReference
    @DateTime
    timestamp: string = new Date().toISOString()

    value: number = 0
}
```

## Query

### `@Query(statement)`

Method decorator that defines a [named query](/apps/persistence/named-queries) on a repository class. The statement is a `SELECT`, `INSERT`, `UPDATE` or `DELETE` of the repository's entity in the [Kinotic SQL grammar](/apps/reference/migration-sql-grammar), including an aggregate `SELECT` (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, …), with `:paramName` parameter binding. The method body is left empty -- `kinotic generate` fills in the implementation. Declare the method on the repository subclass that extends the generated base class (the subclass is generated once and never overwritten).

```typescript
import { Query } from '@kinotic-ai/persistence'

export class ProductRepository extends BaseProductRepository {

    @Query('SELECT * FROM Product WHERE category = :category ORDER BY name')
    findByCategory(category: string): Promise<Product[]> {
        // Implementation is generated by the CLI
    }

    @Query('SELECT COUNT(*) AS count FROM Product WHERE category = :category')
    countByCategory(category: string): Promise<CategoryCount[]> {
        // Implementation is generated by the CLI
    }
}
```

## Service Decorators

These decorators are imported from `@kinotic-ai/core`.

### `@Publish(namespace?, name?, advertise?)`

Publishes a class as a remotely accessible service. The service becomes available to clients via the RPC gateway, addressed inside the client's zone (see [CRI Format](/platform/reference/cri-format)).

```typescript
import { Publish } from '@kinotic-ai/core'

@Publish('com.example')
class UserService {
    async findUser(id: string): Promise<User> {
        // ...
    }
}

@Publish('com.example', 'CustomName')
class MyService {
    // Published as com.example.CustomName
}

@Publish('com.example', undefined, true)
class OrderService {
    // Also advertised in the service directory
}
```

**Parameters:**
- `namespace` — Optional service namespace (e.g., `'com.example'`)
- `name` — Optional custom service name. Defaults to the class name.
- `advertise` — When `true`, the service advertises itself in the platform service directory, so it appears in directory listings for browsing and invocation. Defaults to `false`: the service is callable over RPC but not listed.

A client's request to the service is checked against the authorization the class declares, so a class that should be callable carries [`@AuthzResource` or `@AuthzUnchecked`](#authorization-decorators).

### `@Zone(zone)`

Declares the zone a service is addressable in, relative to the client's `Kinotic.zonePrefix`. When absent, `Kinotic.defaultZone` (typically loaded from the project `package.json` `kinotic.zone` field) applies. The zone is one or more dot-separated labels of lowercase letters, digits, and interior dashes.

```typescript
import { Publish, Zone } from '@kinotic-ai/core'

@Zone('billing')
@Publish()
class InvoiceService {
    // With zonePrefix app.acme-org.orders-app → srv://app.acme-org.orders-app.billing~InvoiceService
}
```

### `@Version(version)`

Sets the semantic version for a published service. Enables versioned service routing.

```typescript
import { Publish, Version } from '@kinotic-ai/core'

@Publish('com.example')
@Version('2.0.0')
class UserService {
    // ...
}
```

### `@Scope`

Marks the getter or method that provides the scope for service routing. Scope targets requests at one specific instance of a service, such as the copy running on a particular node.

```typescript
import { Publish, Scope } from '@kinotic-ai/core'

@Publish('com.example')
class NodeManager {
    nodeId: string = ''

    @Scope
    get scope(): string {
        return this.nodeId
    }
}
```

### `@Context`

Marks a method that receives the request context: a `ServiceContext` whose `participant` is the calling participant, as the gateway authenticated it, plus whatever the registered `ContextInterceptor` adds. This is the TypeScript counterpart of a Java service's `Participant` parameter.

**The context parameter must be the method's final parameter.** Callers never pass it — the platform appends it after the caller-supplied arguments, so a context parameter anywhere else will receive a caller argument instead.

```typescript
import { Publish, Context, type ServiceContext } from '@kinotic-ai/core'

@Publish('com.example')
class AuditService {
    @Context
    async logAction(action: string, context: ServiceContext): Promise<void> {
        console.log(`${context.participant?.id} performed ${action}`)
    }
}
```

`participant` is absent only for an invocation that originated inside the platform with no participant bound, such as a scheduled job. See [Publishing Services](/apps/services/publishing-services#context) for narrowing it to a scope-typed participant.

## Authorization Decorators

These decorators are imported from `@kinotic-ai/core`. They declare what every function of a published service is checked for before the service sees a request; see [Access Control](/platform/access-control) for the roles and grants a check is answered from. `kinotic generate` and `kinotic sync` read them from the class's source into the service's definition, so their arguments are literals, and the system derives each function's check from the definition when the runtime registers the service. A service in an application's zone is served to clients only with them: a function whose definition neither checks it nor marks it unchecked is refused at the gateway, as is every function of a service the project declares no definition for.

### `@AuthzResource(declaration)`

Marks a class as acting on one type of resource, so every function's check is derived from its name and parameters. The declaration is the type, or an object:

| Field | Meaning |
|---|---|
| `value` | The resource type, a lowercase identifier such as `report`. It prefixes the type's permissions (`report_can_read`) and roles (`report.editor`) |
| `parent` | The type containing this one, such as `tenant`. A grant on the parent reaches every resource of this type inside it, and a function naming no resource of its own, a listing or a create, is checked on the parent |
| `resourceId` | The resource every function is checked on, for a service whose functions act on one resource the request does not name: `{@applicationId}`, `{@tenantId}` or a literal id |
| `permission` | The permission every function needs unless it declares its own, as a short name such as `can_manage` |
| `roles` | Roles of the type beside the built-in viewer, editor and admin, each `{id: '<type>.<level>', permissions: [...]}` naming permissions the type's functions need |

```typescript
import { AuthzCheck, AuthzResource, AuthzUnchecked, Publish } from '@kinotic-ai/core'

@AuthzResource({value: 'report', parent: 'tenant', roles: [{id: 'report.generator', permissions: ['can_generate']}]})
@Publish('com.example')
class ReportService {
    // report_can_read on the report id names
    async findById(id: string): Promise<Report> { /* ... */ }

    // report_can_edit on the report report.id names
    async save(report: Report): Promise<Report> { /* ... */ }

    // report_can_read on the caller's tenant
    async findReports(): Promise<Report[]> { /* ... */ }

    // report_can_generate on the report reportId names, answered from the stored relationships
    @AuthzCheck({permission: 'can_generate', consistent: true})
    async generate(reportId: string): Promise<void> { /* ... */ }

    // served with no check
    @AuthzUnchecked
    async ping(): Promise<string> { return 'pong' }
}
```

The permission is derived from the first word of the function's name: `find`, `get`, `count`, `search` and `list` need `can_read`; `save`, `update` and `set` need `can_edit`; `delete` and `remove` need `can_delete`; `create` needs `can_edit` of the type on the parent. `can_delete` implies `can_edit`, which implies `can_read`. A function whose name starts with any other word declares its permission with `@AuthzCheck`, or the service's registration fails.

The resource's id is the parameter named `id` or `<type>Id` (`reportId` for `report`), else the `id` of the first object parameter that has one. A function with neither is checked on the parent, whose id is found the same way with the parent's name, else on the caller's own scope (`{@organizationId}`, `{@applicationId}` or `{@tenantId}`).

### `@AuthzCheck(declaration)`

States a part of one function's check that derivation gets wrong or cannot know. Every field left out keeps the derived value, or the one the class declares with `@AuthzResource`.

| Field | Meaning |
|---|---|
| `permission` | The permission the function needs, a short name such as `can_generate`; in the model it is prefixed by the type, `report_can_generate` |
| `resource` | The type of the resource the check is made on, when it is not the service's own, such as the parent. A type name, never a template |
| `resourceId` | The id of the resource, a template: `{reportId}` is a parameter's value, `{registration.id}` a property of an object parameter, `{@tenantId}` the caller's scope |
| `implies` | Short names of permissions of the same type this one also grants, so `implies: ['can_read']` lets a role bundling `can_generate` read what it generates |
| `consistent` | `true` for a function whose check must be answered from the stored relationships rather than the engine's caches, because a stale allow would be a security event |

A template naming a parameter the function does not have fails the service's registration.

### `@AuthzUnchecked`

On a method, serves that function with no check; on a class declaring no resource, serves every function of it, inherited ones included, with no check. Any caller the service's zone admits may call it, and the service answers only what the caller may see or do: it is for a function with no resource to check, such as a listing of the caller's own data, and a service whose every function answers for the caller alone. A method carrying it and `@AuthzCheck`, a method carrying either on a class marked as a whole, and a class carrying it and `@AuthzResource`, fail `kinotic generate`.

A runtime refuses to register a class carrying `@AuthzResource` or `@AuthzUnchecked` that the project declares no definition for, with an error asking for `kinotic sync`, and the directory refuses a definition in which a function declares `@AuthzCheck` while the class declares no resource.

### Java annotations

A system service declares the same things on its `@Publish` interface with the annotations in `org.kinotic.idl.api.annotations`, and the system derives its checks the same way when the service's contract is created. The names the system's services share, the types (`AuthzConstants.PROJECT_TYPE`), the permissions (`AuthzConstants.CAN_MANAGE_MEMBERS`) and the built-in role levels, are constants of `org.kinotic.idl.api.utils.AuthzConstants`.

| Annotation | Target | Attributes |
|---|---|---|
| `@AuthzResource` | interface | `value`, `parent`, `resourceId`, `permission`, `roles`, as above |
| `@AuthzRole` | inside `roles` | `id` (`<type>.<level>`), `permissions` |
| `@AuthzCheck` | method | `permission`, `resource`, `resourceId`, `implies`, `consistent`, as above, and `permissionResolver` |
| `@AuthzUnchecked` | method, or an interface declaring no resource | none |

```java
@Publish
@AuthzResource(value = "vm_node", parent = AuthzConstants.SYSTEM_TYPE,
               roles = @AuthzRole(id = "vm_node.registrar", permissions = AuthzConstants.CAN_REGISTER_NODE))
public interface VmNodeOrchestrationService {

    // vm_node_can_register_node, checked on the system, where the node is not yet
    @AuthzCheck(resource = AuthzConstants.SYSTEM_TYPE, permission = AuthzConstants.CAN_REGISTER_NODE)
    Future<VmNode> registerNode(VmNodeRegistration registration);

    // vm_node_can_report on the node nodeId names
    @AuthzCheck(permission = AuthzConstants.CAN_REPORT, resourceId = "{nodeId}")
    Future<VmNode> heartbeat(String nodeId, List<String> problems);
}
```

`permissionResolver` names a resolver that decides the permission of each request from the function's arguments, in place of `permission`, for a function whose permission depends on what the request selects. The entities repositories' `namedQuery` and `namedQueryPage` declare `permissionResolver = AuthzConstants.NAMED_QUERY_PERMISSION_RESOLVER`, which decides from the query's statement. A resolver runs on whichever server receives the request, so every server holds it: it names the parameters it reads and every permission it may require, each with the reason a request needs it. The contract records those permissions, the model holds each of them, and a request is checked for the one the resolver decides, which must be among them. Declaring `permission` or `implies` beside a resolver, naming one no resolver has, or a resolver reading a parameter the function lacks fails the service's registration. Only the system's own services name a resolver; a runtime's definition naming one is refused.

In Java the id parameter is a `String`, and an object parameter's `id` is the property of its converted type. A function's check is read from the interface's most specific declaration of it, so an interface redeclares a function it inherits, such as `findById` of `CrudService`, to give it a check of its own. A parameter the system supplies, such as the caller's `Participant`, is not part of the request and cannot be referenced. A function of an interface carrying `@AuthzResource` that derives no check and declares none fails the service's registration, as does `@AuthzCheck` or `@AuthzUnchecked` on a function of an interface declaring no resource, and `@AuthzUnchecked` beside `@AuthzResource` on the interface.
