---
title: Calling Services over HTTP
description: Invoking a published service function with a plain HTTP request.
---

A client that has no STOMP connection, such as a script, a webhook or a function running on a serverless platform, can call any published service function with one HTTP request to the gateway of the server it would connect to.

```bash
curl -X POST "https://<api host>/api/srv/app.acme-org.orders-app~com.acme.OrderService/findById" \
     -H "Content-Type: application/json" \
     -H "Authorization: Bearer <token>" \
     -d '["order-42"]'
```

## The request

- **Path:** `POST /api/srv/` followed by the function's address without its `srv://` scheme, so `srv://app.acme-org.orders-app~com.acme.OrderService/findById` is `/api/srv/app.acme-org.orders-app~com.acme.OrderService/findById`. A version is appended to the function with its `#` escaped as `%23`: `.../OrderService/findById%231.0.0`.
- **Body:** the function's arguments. With `Content-Type: application/json` it is a JSON array of the arguments in order. With `Content-Type: application/x-kinotic-named-json` it is a JSON object keyed by parameter name, which needs the service's definition (see [the service directory](/apps/services/publishing-services#the-service-directory)). Any other content type is refused with `415`. A body is limited to 16 KB.
- **Credentials:** the same headers a STOMP connection authenticates with, described in [Authentication](/apps/security/authentication): `Authorization: Bearer <token>`, or `clientId` and `clientSecret` with the scope headers. Every request authenticates on its own.
- **Tracing:** a W3C `traceparent` header, and `tracestate` with it, continues the caller's trace into the service.

A request may address only the zones a STOMP connection of the same participant may send to; any other address is refused with `403`.

## The response

| Status | Meaning |
| --- | --- |
| `200` | The function's result, in the content type the service replied with, normally `application/json` |
| `400` | The path names no service function, or the body cannot be read |
| `401` | The credentials were refused |
| `403` | The participant may not call that address |
| `404` | No service is serving that address |
| `415` | The body is not one of the two accepted content types |
| `500` | The function failed; the body is `{"error": "<message>"}` |
| `503` | The service went away before it answered |

A function answers over HTTP with a single result, so a function that returns a stream cannot be called this way.
