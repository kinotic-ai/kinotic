---
title: Publishing Services
description: How to publish TypeScript services in Kinotic using decorators.
---

Use the `@Publish` decorator to expose any TypeScript class as a remote service. The namespace you pass to `@Publish` combined with the class name forms the service identifier that callers use to reach it.

## Basic Example

```typescript
import { AuthzUnchecked, Publish, Version } from '@kinotic-ai/core'

@Version('1.0.0')
@Publish('com.example')
@AuthzUnchecked
class GreetingService {
    hello(name: string): string {
        return `Hello, ${name}!`
    }

    add(a: number, b: number): number {
        return a + b
    }
}
```

This registers the service as `com.example.GreetingService` at version `1.0.0`, in the zone the client is configured for (see [Zones](#zones) below — an application's services register under its `app.<org>.<app>` zone). Every public method on the class becomes a remotely callable operation. `@AuthzUnchecked` lets any caller the zone admits call every one of them; a service whose functions act on your application's resources declares those instead, as [Authorization](#authorization) describes.

## Zones

Every service address lives in a zone — the isolation boundary the gateway validates on each call (see [CRI Format](/platform/reference/cri-format)). An application's services always register inside the application's own zone: the client's `zonePrefix` is set from static project configuration before services are instantiated, and declared zones are appended to it, so a service can never register outside its application.

```typescript
import { Kinotic } from '@kinotic-ai/core'
import { appZone } from '@kinotic-ai/management-api'
import config from './.config/kinotic.config'

// In your application's entry point, before any @Publish class is instantiated
Kinotic.zonePrefix = appZone(config.organizationId, config.applicationId)
```

`@Publish` classes may be instantiated before or after `Kinotic.connect()`: a
registration made before the connection is up queues and subscribes once it is, and
every registration re-subscribes automatically on reconnect — including across an
explicit `disconnect()` / `connect()` cycle.

```typescript
@Publish()                       // → srv://app.acme-org.orders-app~OrderService
class OrderService { ... }

@Zone('billing')                 // → srv://app.acme-org.orders-app.billing~InvoiceService
@Publish()
class InvoiceService { ... }
```

A default zone for every service in the project can also be declared in `package.json`; a class-level `@Zone` overrides it:

```json
{ "kinotic": { "zone": "billing" } }
```

```typescript
import pkg from './package.json' with { type: 'json' }
Kinotic.defaultZone = pkg.kinotic?.zone ?? null
```

The gateway rejects any send or subscribe outside the zones the authenticated participant may address, so a wrong or missing zone routes nowhere — it can never reach another application.

## Registering on a specific client

`@Publish` registers every instance with the global `Kinotic` client. A service hosted on a client you created yourself — a second `KinoticSingleton`, connected under its own credentials or to another server — is registered through that client's `serviceRegistry` with a `ServiceIdentifier` naming the namespace, the service name, and the full zone:

```typescript
import { KinoticSingleton, ServiceIdentifier } from '@kinotic-ai/core'

const host = new KinoticSingleton()
await host.connect({ server: { host: 'localhost', port: 58505 }, credentials })   // the app server

const identifier = new ServiceIdentifier('com.example', 'GreetingService', 'app.acme-org.orders-app')
host.serviceRegistry.register(identifier, new GreetingService())   // → srv://app.acme-org.orders-app~com.example.GreetingService

// later, when the service should no longer be reachable
host.serviceRegistry.unRegister(identifier)
```

The zone is the complete zone the service lives in: `zonePrefix` and `defaultZone` apply to `@Publish` classes only. Registering the same identifier twice on one client is a no-op, and `unRegister` ends any stream the service is still producing with an error to its caller.

## The service directory

Every published class under the project's `servicesPaths` gets a service definition from `kinotic generate` and `kinotic sync`, its functions with their parameters and types, written to the `ServiceDefinitions` module under `generatedPath`. A project that imports that module has the runtime register each service in the system's service directory as the service comes online: the services registered before `connect` when the client connects, and a service registered on a connected client as it registers. Only a service in an application's zone, `app.<organizationId>.<applicationId>` or a zone under it, is registered, through the system's `ApplicationServiceDirectory` in `app-api`, which refuses a zone that is not the application's, an application outside the caller's organization, and a caller that does not hold `application_can_register_services` on the application, which the application's `application.runtime` role bundles. A deployment grants that role to the runtime machine of each of the project's microservices, so a runtime registers and hosts its own application's services and no other's. The directory then holds the application's services beside the system's own, with their liveness, and each definition is the contract every request to the service is checked against: a service the project declares no definition for is listened on in its zone, but the gateway refuses every client request to it. A definition naming other functions than the class serves fails the registration, and with it the connection, until `kinotic sync` runs again.

### Authorization

Every request a client makes to one of your services is checked at the gateway before the service sees it, against the checks the system derived from the service's definition when the runtime registered it (see [Access Control](/platform/access-control)). A class declares them with the [authorization decorators](/apps/reference/decorators#authorization-decorators), which `kinotic sync` reads into the definition:

```typescript
import { AuthzCheck, AuthzResource, Publish } from '@kinotic-ai/core'

@AuthzResource({value: 'report', parent: 'tenant'})
@Publish('com.example')
class ReportService {
    async findById(id: string): Promise<Report> { /* ... */ }      // report_can_read on the report
    async findReports(): Promise<Report[]> { /* ... */ }           // report_can_read on the caller's tenant

    @AuthzCheck({permission: 'can_generate'})
    async generate(reportId: string): Promise<void> { /* ... */ }  // report_can_generate on the report
}
```

- `@AuthzResource` names the type the class acts on, and each function's permission and object are derived from its name and parameters; `@AuthzCheck` states what the derivation gets wrong or cannot read.
- `@AuthzUnchecked` on a function, or on a class declaring no resource, serves it with no check, to any caller the zone admits.
- A function of an `@AuthzResource` class that derives no check and declares none fails the service's registration until the class declares one and `kinotic sync` runs again.
- A function the definition neither checks nor marks unchecked is refused, which is every function of a class carrying neither decorator.

Your application's model then carries the type, its permissions, its built-in `report.viewer`, `report.editor` and `report.admin` and the roles the class declares, which an organization member grants your application's users through `ApplicationAccessService`. A request from one of the application's users is checked in the application's own authorization store.

### Parameter and return types

Arguments and results travel as JSON, so a function's types are published as JSON carries them:

- A `Promise` or `PromiseLike` result is asynchronous and an `Observable` result is a stream, of the type it resolves to or emits.
- `any`, `unknown`, and a type parameter with no constraint accept anything; a constrained type parameter is its constraint.
- Interfaces, classes (their fields, without their methods), generic instantiations such as `Page<Report>`, mapped types such as `Partial<Report>` and `Pick<Report, 'id'>`, intersections, and unions of objects are objects, named for the type and its type arguments (`Page_Report`, `Partial_Report`).
- `Record<string, V>` and `{[key: string]: V}` are maps, enums are enums, and a union of string literals is a string.
- A `Date` is published as a date, but it arrives as the ISO-8601 string a date travels as: the service receives a string, and a TypeScript caller gets a string back. `kinotic generate` logs a warning for each one, and the directory carries the same warning in the `warnings` metadata of the parameter, or of the function for a result.
- A `Map`, `Set`, `Uint8Array`, `Buffer`, `bigint`, tuple, or function fails generation with the reason and the type to declare instead.

## Decorators

### @Publish(namespace?, name?, advertise?)

Marks a class for publication. The full service identifier becomes `namespace.ClassName`; both parts are optional (the name defaults to the class name). A service published with no namespace is addressed by its name in its zone, `srv://<zone>~ClassName`, and the platform's service directory names it in its zone's namespace, `<zone>.ClassName`, so services of the same name in different applications stay apart. Passing `advertise` as `true` additionally advertises the service in the platform service directory, so it appears in directory listings for browsing and invocation — publishing alone makes a service callable over RPC without listing it.

### @Zone(zone)

Declares the zone the service is addressable in, relative to the client's `zonePrefix`. The zone is one or more dot-separated labels of lowercase letters, digits, and interior dashes.

### @Version(version)

Sets the semantic version for the service in `X.Y.Z` format. Callers can pin to a specific version when resolving the service.

### @Scope

A getter or method decorator that marks the member providing the scope identifier. Scope targets requests at one specific instance of a service — for example the copy running on a particular node or device.

```typescript
import { Publish, Scope } from '@kinotic-ai/core'

@Publish('com.example')
class DeviceService {
    deviceId: string

    @Scope
    get scope(): string {
        return this.deviceId
    }

    constructor(deviceId: string) {
        this.deviceId = deviceId
    }

    getStatus(): string {
        return `Status for device ${this.deviceId}`
    }
}
```

When a caller targets a specific scope (e.g., `device-42`), the platform routes the request to the instance whose `deviceId` matches.

### @Context

A method decorator that marks a method as receiving the request context: a `ServiceContext` carrying the calling participant — the same caller a Java service receives as its `Participant` parameter — plus whatever a registered `ContextInterceptor` adds.

**The context parameter must be the method's final parameter.** Callers never pass it — the platform appends it after the caller-supplied arguments.

```typescript
import { Publish, Context, type ServiceContext } from '@kinotic-ai/core'
import { isOrganizationParticipant, requireParticipant } from '@kinotic-ai/management-api'

@Publish('com.example')
class OrderService {
    @Context
    async listOrders(status: string, context: ServiceContext): Promise<Order[]> {
        const caller = requireParticipant(context.participant, isOrganizationParticipant)
        return this.orders.findByOrganization(caller.organizationId, status)
    }
}
```

`context.participant` is the participant the gateway authenticated on the calling connection, serialized with its scope discriminator and ids (`type`, `organizationId`, `applicationId`). It is absent only for an invocation that originated inside the platform with no participant bound, such as a scheduled job.

`requireParticipant` is the counterpart of a Java service's `securityContext.requireParticipant(OrganizationParticipant.class)`: it returns the participant narrowed by the guard you pass (`isSystemParticipant`, `isOrganizationParticipant`, or `isApplicationParticipant`), throws if the invocation carries no participant, and fails the invocation with an `AuthorizationException` — the same name a Java refusal carries — when the caller does not hold that scope. The guards alone narrow without throwing, for a method that serves more than one scope.

A `ContextInterceptor` registered through `Kinotic.serviceRegistry.registerContextInterceptor(...)` receives the context with the participant already set and returns the context the method sees, so it can add data derived from the caller or from the request headers:

```typescript
Kinotic.serviceRegistry.registerContextInterceptor({
    async intercept(event, context) {
        return { ...context, tenant: await tenants.forParticipant(context.participant) }
    }
})
```
