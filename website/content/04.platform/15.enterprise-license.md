## Enterprise Features

The Enterprise Features are every Enterprise Implementation, which is any file in a Java package
with a segment named `ee` other than an Enterprise Extension Point, and the capability of every
Enterprise Extension Point. They live in the module each one belongs to, such as
`org.kinotic.domain.internal.api.ee` in `kinotic-domain`.

| Enterprise Feature | Free alternative |
|---|---|
| Azure Key Vault secret storage (`kinotic.domain.secretStorage.backend: AZURE`) | In-memory secret storage (`backend: IN_MEMORY`, the default), which keeps secrets in process memory and loses them on restart |
| Okta and Microsoft Entra ID sign-in through an organization's own client, at the organization's login, an application's login or a tenant's login | Google sign-in through the organization's own client. Microsoft sign-in through Kinotic's managed registration is not an Enterprise Feature |

The org, system and app servers include the Enterprise Features, so the published server images
contain them. An Enterprise Feature that is present but not turned on is not in production use, and
having one in an image does not license its production use.

## License key

A server turns an Enterprise Feature on only while the cluster's installed License Key from Minds Ignited lists the
feature, or `*` for every feature, and has not ended its grace period. A key keeps its features on for 14 days
after it expires, while the server logs a warning, and turns them off when the grace period ends. Every server
decides at each use, so installing a new key, or a key expiring, takes effect without a restart, except where the
table below says a feature keeps working after its key lapses.

The whole cluster runs on one installed key, held in Elasticsearch. It is installed in two ways:

- **At startup.** A server whose `kinotic.ee.licenseKey` property (the `KINOTIC_EE_LICENSEKEY` environment
  variable) holds a valid key issued later than the installed one, or when no valid key is installed, installs
  the property's key as it starts.
- **While running.** A system user pastes a key on the system console's **License** page, or installs it with
  the system API's `LicenseService.install`, which verifies it and installs it; every server runs on it as the
  call completes. A server that missed the notice, or could not read the key then, reads it at its next reload, which it tries every ten minutes. The License page shows the licensee,
  status, expiry, grace period end and features of the installed key, which `LicenseService.findCurrent` returns.

Keys are verified offline, and each server logs the licensee, expiry and features a key turns on, or why the key is
not valid.

The local Docker Compose stack in `deployment/docker-compose/` sets the Kinotic evaluation license key, which
turns on every Enterprise Feature until the end of 2036 for development and testing only. The published server images
carry no key.

| Feature named in the key | Without it |
|---|---|
| `AZURE_KEY_VAULT` | A server set to `kinotic.domain.secretStorage.backend: AZURE` refuses to start. A running server keeps using Azure Key Vault when its key lapses, since switching backends would lose every secret |
| `ENTERPRISE_IDENTITY_PROVIDERS` | Saving or editing an Okta or Microsoft Entra ID configuration that uses an organization's own client is refused. Configurations already saved keep signing people in |

## Enterprise Extension Points

Any interface, abstract class, or annotation in a Java package with a segment named `ee`, such as
`org.kinotic.domain.api.ee.services`, or in a directory named `ee`, is an Enterprise Extension
Point. The extension point itself is Elastic-licensed, so you can read it
and build against it, but the capability it provides is an Enterprise Feature.

For production use, the license does not permit you to:

- implement or extend an Enterprise Extension Point, or use such an implementation, other than
  an Enterprise Implementation or one included in the Elastic-licensed code and used unmodified
- modify Kinotic to move a type out of an `ee` package, or to replace, bypass or wrap an
  Enterprise Extension Point or the code that uses it, so that other software provides its
  capability
- provide the capability of an Enterprise Extension Point in any other way designed to avoid the
  need for an enterprise license

## What each use requires

| Use | Requires |
|---|---|
| Reading, building, modifying and testing the Enterprise Features, locally or in a non-production environment that serves no end users, customers or business operations | Accepting the Kinotic Enterprise License, which you do by using them |
| Writing your own implementation of an Enterprise Extension Point for development and testing | Nothing beyond the Elastic License 2.0 and the Kinotic Additional Limitations |
| Running an Enterprise Feature in production | A written agreement with Minds Ignited that permits that use, and a valid License Key wherever Minds Ignited has issued one for that feature |
| Running Kinotic in production without the Enterprise Features | The Elastic License 2.0 and the Kinotic Additional Limitations: no agreement, provided each Enterprise Extension Point runs only the implementation included in the Elastic-licensed code, unmodified |

A written agreement that permits only limited purposes, such as evaluation or a proof of concept,
licenses production use for those purposes alone. The Enterprise Features may be redistributed
only unmodified, with the Kinotic Enterprise License, as part of a copy of Kinotic distributed
under the Elastic License 2.0, and may not be offered to third parties as a hosted or managed
service, and the Elastic License
2.0 forbids offering Kinotic itself as a hosted or managed service that gives users access to a
substantial set of its features.

To arrange an enterprise agreement, contact Minds Ignited through [kinotic.ai](https://kinotic.ai).
