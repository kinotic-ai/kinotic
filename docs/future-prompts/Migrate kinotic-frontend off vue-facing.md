# Migrate kinotic-frontend off vue-facing-decorator class components → `<script setup>`

## Objective
Convert the Vue SFCs in `kinotic-frontend` from `vue-facing-decorator` class
components (`@Component class X extends Vue`) to the Composition API
(`<script setup lang="ts">`), eliminating TypeScript legacy decorators from the
Vue layer. This is a behavior-preserving refactor.

## Why this matters
A version-bump commit (`4358c48`, "fix: for versions") moved the frontend to
Vite 8, which transpiles with **Oxc** instead of esbuild. **Oxc does not implement
TypeScript legacy (`experimentalDecorators`) decorators**, so every `@Component`
page shipped a raw `@Component` token to the browser → `SyntaxError: Invalid or
unexpected token (at Login.vue:26:1)` → blank screen. As a stopgap the frontend
was pinned back to **Vite 6** (`vite ^6.3.5`, esbuild) in commit `4160369`.
Dropping class components removes the Vue-layer decorators and keeps the app
aligned with where Vue tooling is going (everything is `<script setup>` now).

## Scope (verify with a fresh grep — these are from an earlier assessment)
- ~**36 SFCs** under `kinotic-frontend/src` use `vue-facing-decorator`.
- All are **flat** `@Component class X extends Vue` — **no component inheritance,
  no mixins, no `@Provide/@Inject`**. This is the easy case; it's volume + care,
  not architectural puzzles.
- Decorators in use: `@Component` (36), `@Prop` (~53 / 15 files),
  `@Watch` (~18 / 7 files), `@Emit` (~11 / 2 files), `@Ref` (~8 / 2 files).
- Lifecycle hooks: `mounted` (~20), `beforeUnmount` (~5), `created` (1),
  `beforeMount` (1) — all have direct equivalents.
- `vue-facing-decorator@4.0.1`, Vue `3.5.x`. Frontend uses **pnpm**
  (NOT bun — bun is only for `kinotic-js/workspace`).
- The `extends Base*Repository` classes are the persistence/EntityRepository
  data layer, NOT Vue components — leave them alone.

## Conversion mapping
- `@Component({ components })` + `extends Vue` → `<script setup lang="ts">`
  (imported components are auto-available; drop the `components` registration)
- class fields (data) → `ref()` / `reactive()`
- getters (computed) → `computed()`
- methods → plain functions
- `mounted/beforeUnmount/created/beforeMount` → `onMounted/onBeforeUnmount/setup-body/onBeforeMount`
- `@Prop() foo: T` → `defineProps<{ foo?: T }>()` (mind required/default/type)
- `@Emit('x')` / `this.$emit` → `defineEmits<{...}>()` + `emit(...)`
- `@Watch('x', { immediate, deep })` → `watch(x, ..., { immediate, deep })`
- `@Ref` / `this.$refs.x` → template ref via `ref()`
- `this.$route / this.$router / this.$nextTick` → `useRoute() / useRouter() / nextTick()`
- `this.foo` → `foo.value` in `<script>` (templates auto-unwrap)

## Approach
1. **Do a pilot first** — suggest `src/pages/login/Login.vue` (moderate: data,
   methods, fetch, router, a `@Ref`). Establish the pattern, show me the diff,
   confirm before bulk work.
2. Both styles coexist fine under Vite 6, so migrate **incrementally, one SFC per
   commit**, building/checking after each. There's no reliable codemod for
   `vue-facing-decorator`; expect careful hand conversion. The main risk is
   reactivity bugs from `this.x` → `x.value` — verify each component renders.
3. Match the style of the SFCs already written as `<script setup>` in the repo.

## Important related blocker — do NOT assume this unblocks Vite 8 by itself
The frontend ALSO uses **idl entity-definition decorators** in source —
`@Entity` (×3), `@AutoGeneratedId` (×3), `@NotIndexed` (×2) on the Dashboard /
DashboardWidget / DataInsightsWidget models (from `@kinotic-ai/idl`). Oxc breaks
those too. So returning to Vite 8 needs those resolved separately (e.g. define
those entities in a pre-compiled package, or move idl off legacy decorators).
Treat re-enabling Vite 8 / unpinning `vite` as OUT OF SCOPE for this task unless
explicitly asked — just flag the entity-decorator dependency.
